# /heli · 海上油田直升机运载编排 · 三维实时海图

2026「策联杯」数学建模精英联赛 **B 题问题三最终提交方案**的可视化。
图上每一架直升机的位置、每一次停靠、每一位乘客坐哪一班，都直接来自提交文件，
没有任何演示用的假数据。

## 页面

| 路径 | 说明 |
|---|---|
| `/heli/` | 三维海图。海面 / 陆地 / 52 座平台 / 3 座机场 / 24 架直升机全部按真实时刻推演 |
| `/heli/terminal.html?id=A01` | 机场候机厅：出发到达航班牌、停机坪、旅客名册 |
| `/heli/terminal.html?id=F024` | 海上设施：停机甲板状态、甲板日志、人员进出 |

`/heli/*` 在 `functions/_middleware.js` 里放行为公开路径（与 `/dc` 同理），
所以不登录也能打开、可以直接把链接发给别人。

## 时间

方案覆盖 **2026-08-03（周一）～ 08-09（周日）**，正好一个完整星期。
页面默认把**现实中的星期几与时刻**一一映射到计划里的同一时刻（LIVE 1:1）；
也可以暂停、调 1/10/60/240 倍速、拖时间轴、按 1..7 跳到某一天。
时钟状态存在 `sessionStorage['heli-clock-v1']`，海图与候机厅两页之间来回切换不会跳时间。

## 数据

`data/plan.json`（约 570 KB）由 `data/build_plan.py` 生成，输入是三份原始文件：

```
Desktop\B题工作区\submit\q3-routes.csv        798 行，171 个架次的逐站时刻表
Desktop\B题工作区\submit\q3-assignments.csv   4000 行，每人坐哪一班、第几站上下
Desktop\2026策联杯B题\...\peopleQ3.csv        4000 人的起终点、时间窗、任务类型
Desktop\B题工作区\coords.csv                  距离矩阵做 MDS 得到的平面坐标
```

重新生成：

```bash
py -3 review-site/heli/data/build_plan.py
```

脚本会顺带把 T / P / U / 燃油重新算一遍并打印出来，**必须和论文对得上**：

```
T = 31281 分（521.35 h）   N = 171 架次   P = 261035（人均 65.3）
燃油 242760 kg             U = 56.70%     临时任务 156/160
下界 24536，间隙 21.56%
```

坐标用的是对题目距离矩阵做 MDS 的结果，**平均相对误差 0.5%、最大 3.6%**，
所以图上量出来的距离基本就是题目给的距离。

## 实现要点

- 纯 vanilla + three.js **0.160.0 全局构建**（CDN，`build/three.min.js`，r160 是最后一个带全局构建的版本，
  所以版本号锁死不要动）。无打包、无框架，和站点其余部分一致。
- 1 世界单位 = 1 km。海岸线是一条解析曲线 `coastZ(x)`，**海面着色器（GLSL）与陆地高程（JS）用的是同一条**，
  两边改必须一起改，否则海陆边界会错开。
- 海面法线来自 5 组解析行波（正弦 + 解析导数）。早期版本用逐像素 fbm 采样，
  在集显上只有 23 FPS——这类场景是**填充率**瓶颈，不是几何或 draw call。
- 同样出于填充率考虑：沉在海面以下的陆地三角形在建几何时就从索引里剔掉；
  夜灯发光片白天整体隐藏；`adaptRes()` 按帧率在 0.75～1.5 之间自动调 devicePixelRatio。
- 52 座平台用 InstancedMesh 拼装（每个部件一个实例网格），全场 draw call 一百多个。
- 面向相机的公告板四元数是 `Math.PI/2 - cam.theta`，写成 `cam.theta + Math.PI/2` 会被背面剔除、
  火炬和夜灯直接不可见——踩过一次。
- 调试钩子：控制台里 `__HW` 是三维世界对象（`__HW.three.scene/camera/renderer`），
  `HELI` 是数据与时钟内核（`HELI.Clock.set(分钟)` 可直接跳时间）。
